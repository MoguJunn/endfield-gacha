## 1. 样本身份与输入前提

### 合池与迁移指标

五类范围键由 `shared/statisticsScopes.js` 白名单统一定义：限定角色 `limited`、限定武器 `weapon_limited`、常驻武器 `weapon_standard`、重构寻访 `extra:reconstruction`、重构申领 `extra:reconstruction_claim`。成员随目录变化；常驻角色、启程、辉光庆典不进入合池。重构子类型遵循既有 canonical subtype 规则；规则信息不足的成员不能静默删除。

合池先逐账号、逐期、逐对象计算，再以对象在当期的身份合并为目标、其他限定、常驻、待分类六星。首获不跨期，不把类别当作虚拟物品。均值由花费频数加权，累计曲线重新计算；出率分母为全部有效结果，六星构成分母仅为六星。账号覆盖使用完整账号身份跨期去重，样本数与账号数分别解释。未知身份不默认常驻，未知花费不填零。

旧指标通过 `buildScopedLegacyStatistics` 按选择范围计算：常规结果排除免费十连与赠送，保留情报书；出货间隔依照账号隔离后的 shared / series / pool 保底范围；`resultsPerTarget` 是常规结果数除以目标数，不是对象首获均值。目标仅精确匹配目录身份，待定结果不计入目标比例的分母。资源使用完整账号相关历史确定拷贝顺序后归属范围，赠送推进持有次数但不产出资源。首段保底区间仍从保存起点计算，不宣称完整游戏历史。

公共与个人读取均只读 `public-statistics-v4` 快照；公共组读取额外校验当前成员与目标配置签名。首次未生成或成员变化时返回等待状态，不使用缺少成员的合计。组不提供理论预测。

`buildPoolObservations` 接收规范化记录。输入层负责数据来源与覆盖证明，计算层不猜测原始字段含义。

```js
{
  id: '稳定记录标识',
  accountKey: '站点用户:游戏账号:区服',
  poolId: '具体一期卡池标识',
  itemId: '稳定物品标识',        // 对象不明但抽取有效时为 null
  rarity: 6,                    // 4、5 或 6
  timestamp: 1234567890,         // 统一时间单位
  sequence: 1,                 // 相同时间内的可信顺序
  kind: 'pull',                // pull、free、infoBook、gift
  newItem: null                 // true、false 或 null
}
```

- 先按完整账号身份分组，再按时间、顺序计算。不同区服即使 UID 相同，也不能合并为一个时间线。
- 同一账号下的记录 ID 必须唯一；重复、未知类型以及非三值的 `newItem` 会被拒绝。
- `newItem: false` 必须来自可信的明确标记；字段缺省归一为 `null`，不能把缺省值补成 false。
- 相同时间内必须有可证明的事件次序，物品 ID 与星级必须一致。这些属于规范化层的前提，当前计算函数尚不验证目录或批次顺序。
- `verified-prefix` 严格模式要求用于实际花费解释的区间连续；真实适配层采用 `stored-period`，仅解释为已记录结果数。接口漏页仍必须拒绝，不能把未读完的保存记录当作完整集合。
- `completeAccounts` 只证明选定一期卡池从起点到观察截止的记录完整，不证明整个账号历史完整。导入成功、记录数量多、发现一个 `newItem: true` 均不能单独作为完整性的证据。
- 跨池记录和赠送不影响当前一期卡池的首次分类。

## 2. 次数、资源与赠送

观测图统一使用“有效抽取结果”作为基本单位：普通抽取、免费十连结果、情报书结果各计一次；直接赠送不计入出率或花费分布。十图由下面八项基础观测及账号覆盖、花费区间两图组成。

- `total`：普通、免费、情报书结果的总数。
- `free`：免费十连产生的结果数。计入观测，不推进常规保底或累计寻访奖励。
- `infoBook`：情报书凭证产生的结果数。计入观测；资源说明单列，不能与免费十连合并解释。
- `resources`：普通抽取结果数，即剔除免费和情报书结果后的次数；不是货币金额，也不推断每次实际用了哪种资源。
- `gift`：直接获得物品的赠送事件，不计入本期抽取次数或首次分类。

观测函数不计算保底进度。继承作用域、情报书是否推进某项保障、赠送后一次性保障是否仍可用，均由独立规则与原始证据判定。

武器的观测出率按“件”理解，当前布局暂统一显示有效结果数。真实接入时，花费图需要申领批次与稳定顺序：无法证明十连内部顺序时不得制造精确的第几件首获。理论武器预测已经使用整次申领（每次 10 件），不预测批次内部落点。

## 3. 本期卡池内首次与花费

唯一口径为本期内第一次抽到该物品，输出固定 `firstMode: 'pool'`，输入不再接受首次范围切换。前一池拥有或本期赠送不改变“本期第一次抽到”的分类。实际界面采用 `firstBasis: 'stored-period'`：从本期第一条已保存有效结果到首次明确命中计数。没有完整前缀的账号仍保持 `prefixVerified: false`，缺失记录可能导致结果偏低。

基础函数保留已存在的 `verified-prefix` 证据模式，供严格覆盖验证和样例使用，其分类为：

- 已观察到本期同对象命中：非首次。
- 没有本期先前命中，但已证明本期前缀完整，或当前记录明确为账号新获得：首次。
- 前缀不明且没有足够证据：分类未知。

本期已有明确命中时，即使后续 `newItem` 标记为 true，也仍按非首次处理。历史非新标记不证明本期曾经获得。

花费始终限定在当前一期：本期有先前命中时取两次命中间的有效结果数；保存记录模式没有先前命中时从本期首条保存记录计数。严格模式仍要求完整前缀才能确定实际首次花费。赠送不重置本期抽取间隔。

对象不明的有效抽取继续计入总数、星级与间隔位置；不能把它删除后缩短抽数。若两次同对象之间出现同星级的对象不明记录，无法确定这是否是更近的一次命中，该间隔列为花费未知。其他星级的对象不明记录不影响此对象间隔的判定。

## 4. 八项基础观测的分母与未知样本

1. 星级出率：该星级结果数 / 全部有效结果数。
2. 物品出率：该物品结果数 / 全部有效结果数。
3. 首次平均花费：分类明确、花费已知的首次样本花费之和 / 该类样本数。
4. 非首次平均花费：同上，改为非首次样本。
5. 首次累计曲线：该对象首次样本中，花费不超过横轴值的样本比例。
6. 首次花费分布：该对象在每个整数花费上的首次获得次数。
7. 非首次累计曲线：同上，使用非首次样本。
8. 非首次花费分布：同上，使用非首次样本。

每个物品的首次、非首次样本独立计算分母；均值、频数与累计曲线使用同一组样本。累计曲线是“已完成且可判定样本”的经验分布，不等同于全部玩家的成功概率。

`observationRange` 仅改变显示范围，补齐零频数并保留裁切起点之前的累计值，不重新归一化分母。无样本显示说明和空值，不能画成真实 0%。单个样本显示阶跃，不平滑成预测曲线。

未知与未完成状态分别输出：

- `unknownClassification`：本期首次类别未知的命中数。
- `unknownCost`：类别已知但成本起点或中间同星级命中不明的命中数。两者按此优先级互斥，不能相加后声称覆盖所有原因。
- `repeatUnfinished`：已命中过此对象，观察截止时又有后续结果但未再次命中的账号数。
- `nonObtainingAccounts`：参与当前池观察但在输入范围内未命中此对象的账号数；前缀不完整时不能解释为账号从未获得。
- `incompleteAccounts`：当前池没有完整前缀证明的参与账号数。

基础函数仅返回实际出现过的物品。真实页面提供星级筛选、对象系列开关；当前后台只返回公开目录中实际命中的物品。当期目录零命中项仍待完善，不能以样例目录冒充完整游戏目录。

### 4.1 目标速览、区间与账号覆盖

真实统计页在原有八图之外增加账号覆盖图、花费区间图，以及目标速览和分布读数。它们只使用定时快照中的账号计数与频数点，不读取原始历史，也不新增后台计算任务。

- 目标速览按卡池的目标配置优先选中本期对象，常驻池不标注 UP。支持选择其他对象；目标没有可用统计时展示空值，不伪造零命中样本。
- 对象列表与图表统一按“本期目标六星 → 本池记录中其他限定六星 → 常驻六星 → 五星 → 四星”排列，同组按中文拼音排序。限定分类来自公开角色目录，不向当前池加入其他池的对象；目录分类缺失时单列“其他六星”。
- 有本期目标的卡池，六星曲线默认勾选本期目标与池内其他限定，常驻池保持全选。目录延迟加载不会覆盖手动选择；“只看本期目标”重复点击仍只显示目标并定位六星，“显示全部”只影响当前可见范围内的选择展示，不将星级改成全部。
- 关注对象使用带头像、分类数量、搜索的列表，支持方向键、Home/End、Enter、Escape、Tab 和点击外部关闭，选中后恢复触发按钮焦点；弹层按视口空间向上或向下展开。
- 分位数采用经验累计分布的逆：按频数累加，取首次达到 `ceil(样本数 × 比例)` 的花费值。中位数为第 50 百分位，区间为第 25–75 百分位，P90 为第 90 百分位。并列样本可能使区间收缩至同一点；空样本返回空值。
- 区间图的所有对象使用从 0 到当前最大 P90 的共同刻度；首次和后续获得可切换，显示各自样本数。它表示已完成且成本可判定样本的分布，不是保底或未来获得保证。
- 获得覆盖账号数为 `participatingAccounts - nonObtainingAccounts`，覆盖率分母为当前范围全部参与账号。重复获得不增加账号数，未知花费不否定已经明确出现的命中。其余账号标为“未记录到获得”，不解释为游戏内未拥有。
- 分布读数按选定对象的完整可用样本计算中位数、P90、可编辑阈值内的样本比例；缩放不重新归一化。没有显示对象或没有已完成样本时显示空值。
- 频数图默认每 10 条记录分组，可选逐条或 20 条。固定边界为 1–10、11–20 等，裁切时边界组仅累计显示范围内的记录，提示框显示实际起止区间。分组不会改变累计曲线或分布读数。

相关验证：`src/utils/__tests__/observationInsights.test.js` 检查加权分位数、分组边界、裁切及覆盖计数；`scripts/verify-pool-statistics-live.mjs` 使用真实快照核对指标、目标头像、筛选联动、空状态及双端布局。

## 5. 可手算的观测样例

账号在旧池已拥有 A。本期依次为普通低星、普通 A、普通 A，且本期前缀完整：

- A 本期首次花费 2，非首次花费 1，旧池拥有不改变此结果。

本期先直接赠送 A，再有情报书低星、免费 A、普通 A：有效结果 3，情报书 1，免费 1，普通资源次数 1。A 本期首次花费 2、非首次花费 1；赠送不成为一次抽取。

若缺少前缀，输入为新获得 A、低星、再次 A、低星：保存记录模式首获为 1、重复为 2，末尾有一个未完成重复区间；严格模式第一次 A 花费未知。两个模式不能混称为已证明完整的实际花费。

四个已完成样本花费为 2、5、5、5：显示范围改为 3–5 后，累计率仍为 25%、25%、100%，频数为 0、0、3。

## 6. 理论模型与规则证据

`targetProbabilityDistribution` 预测固定一期本期 UP 六星的下一次获得，采用确定性的保底状态递推，不使用随机模拟，也不复用经验曲线分母。输入为本期规则、当前距六星次数、一次性保障进度、保障是否已使用、预测范围。

当前规则来源是工作区内游戏详情转录与既有常量：

- 工作区 `_docs/终末地卡池规则/限定池规则.md`：基础六星 0.8%，连续 65 次未出后逐次增加 5 个百分点，80 次六星保障，六星中本期 UP 占 50%，本期前 120 次目标保障仅一次。
- 工作区 `_docs/终末地卡池规则/武器池规则.md`：每次申领 10 件，六星基础 4%，六星中 UP 占 25%，连续三次无六星后第四次保障，连续七次无 UP 后第八次一次性保障。

这些转录尚未补齐可复查的官方页面或原始截图版本，本轮外部检索未能取得新证据。因此规则来源核验仍未关闭；预览不声称已经官方重新认证，也不覆盖尚未核实的复刻混池。

角色模型沿用现有单抽六星概率函数：未获得目标的六星将六星保底归零，未出六星继续累计；尚未使用的一次性目标保障到达阈值时吸收全部剩余概率。历史是否拥有与本期保障是否完成是不同条件。

武器模型每步为整次申领。普通申领目标命中率按 `1 - (1 - 0.04 × 0.25)^10`；六星保障申领按预留一个六星槽假设，目标命中率为 `1 - (1 - 0.25) × (1 - 0.04 × 0.25)^9`。沿用现有模拟器假设，并明确标记“预留六星槽模型估计”。规则转录没有公开批次内部生成及重抽方式，包括五星保障的实现，故上述批次概率均不能标成官方精确概率。

当前预测不包括免费十连策略、赠送、未来卡池和非 UP 目标；这些属于后续规则扩展，不通过任意替换目标占比来套用 UP 保障。

输出包括每一步概率、累计概率、范围外剩余概率，以及 `E[min(T, H)]`（截断花费期望）。只要范围外仍有非零概率，页面就显示“截断期望下界”，不能将数值四舍五入为 0 的尾部当作完整期望。

手算模型：基础六星 50%，第二次六星硬保底，六星中目标占 50%，没有一次性目标保障。第一次目标概率 0.25；第二次目标概率 `0.25 × 0.25 + 0.5 × 0.5 = 0.3125`；两次后剩余概率 0.4375，截断期望为 `1 + 0.75 = 1.75`。自动测试同时验证实际规则的 120 次 / 第八次申领边界、继承保底、保障用过后不重发、概率守恒与单调性。

## 8. 当前真实数据接入

桌面 `/summary`、个人 `/dashboard?view=overview` 和手机 `/m/stats` 在候选代码中使用单池／五类合池十图工作区。左侧为专门设计的 `StatisticsPoolList`，每行为小头像、卡池名、UP 和抽数，复用分组与排序规则；不再纵向堆叠原大卡片。支持搜索、分组收起、原生按钮键盘操作；窄屏可收起。旧指标与资源概览跟随所选范围读取快照，角色图鉴保留独立入口；深色主题及减少动态效果与共享桌面壳层保持一致。

`storedPoolObservations.js` 是真实保存记录的适配层，版本 `stored-pool-observation-v3`：

- 输入是完整的“已保存记录集合”，不是当前 UI 的历史分页；这仍不等于完整的游戏生涯记录。
- 不伪造 `completeAccounts`，以 `firstBasis: 'stored-period'` 明确启用本期保存记录内的首次计数。分类未知和成本未知继续分别统计。
- 旧导入存在 false 默认值污染，因此只把明确 true 视为首次标记；其他值保持未知，先前已知命中仍可证明非首次。
- 已保存记录可能存在内部缺口，重复间隔明确标为 `stored-results`（已记录结果数），不能称为游戏实际资源花费或已证明完整的抽数。
- 武器内部顺序仅用于保存结果的排序；观测间隔不能转换为精确申领成本，理论模型继续按整次申领。
- 缺少账号、时间、记录身份、星级无效或重复的记录排除，并按原因分别计数。缺少对象编号时，允许用公开目录名称／既有别名、星级与角色／武器类型作唯一精确匹配；不使用模糊猜测，也不写回数据库。对象仍不明时保留抽数和星级，单列 `unidentifiedRecords` 与星级明细，不归入具体物品。
- 个人按站点用户、游戏 UID 与区服隔离；切换登录用户立即销毁旧会话数据，迟到响应不得恢复旧账号内容。
- 个人接口由服务端认证结果确定 owner，不接收调用者指定的 owner。切换登录用户立即清空旧结果；公开接口不能读取个人快照。导入业务路径未变，数据库增加变更跟踪触发器。

全服通过 `GET /api/stats?type=pool_observations&poolId=...` 读取持久快照，观测结果位于 `observations`；`pool_counts` 一次返回全部公开卡池的抽数。后台先逐账号计算再汇总，公开响应只包含计数、频数与目录名称，不包含用户／账号／原始记录。个人通过 `personal_statistics` 读取经过认证的 owner 快照，包括分账号单池／合池观测、旧指标、资源、排名及双语图鉴。

Worker 按固定最大 ID、主键翻页、最多八页并行读取完整相关范围。页数不完整或超时明确失败，保留旧结果。领取任务时记录 revision，发布时检查租约及 revision；计算期间发生新增、修改或删除会拒绝发布并重试。页面 GET 不访问历史表、不重算统计。没有变化的卡池／账号跳过计算；全服概览中的活跃人数需要随时间定期更新。

用户反馈的 429 条排除记录均为对象编号为空：380 条有名称并能唯一精确匹配目录，49 条名称也为空且为四星。修正后「冬猎」保存记录 45,905 条，有效抽取结果 45,904、参与账号 443、排除 0；另有 1 条直接赠送不计入有效结果。380 条纳入对应物品，49 条保留总数与星级，并明确展示对象不明。这些数值为验证时刻的结果，会随记录变化。

本轮重新只读计算冬猎：有效结果 47,473、账号 459、六星首次样本 746、排除 0；380 条精确名称匹配和 49 条未知四星仍正确保留。浏览器验证首次三图非空、列表抽数完整、手动获取不改变计算时间、360/390/768/1366/1920 布局及中英亮暗、空池、旧概览和移动路由。个人通过多账号隔离、赠送与拥有数的测试，未使用用户私人登录会话实测。部署验证与边界见调度文档。
