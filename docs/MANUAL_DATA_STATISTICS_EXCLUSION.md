## 原有影响及调整后的规则

原有受控编辑函数直接修改 `history`；定时个人统计、单池／合池统计、旧概率和排名函数均从这张表读取，因此会把手动修改值计入计算。个人分析快照还会生成补充记录的合并指标，并在统计概览展示。本轮修正以上路径。

- 排除范围是登录用户、游戏 UID、区服、卡池的组合。同一范围只要出现已保存的手动添加或修改，全部已有及后续导入记录都不参与全服和个人统计，也不作为其他卡池计算保底或获得次序的上下文。
- 受控修改保留明细上的 `statistics_excluded` 证据；独立的 `account_statistics_exclusions` 每个受影响范围只保存一条小体积标记。修改一条明细也会排除同池其他未修改的记录，其他账号、区服及未修改卡池保留独立统计。
- 跨池移动同时标记原池和目标池。工作台补充记录、截图识别后确认的记录及转换文件存档同样使该范围整池退出统计；未保存草稿不触发标记。
- 对迁移前的 `edit_version > 1` 记录、`manual_` 编号及已有补充记录回填整池排除标记。原有受控编辑是该版本号的递增入口。原池可由旧审计和唯一账号定位时一并回填；缺少旧内容或账号定位有歧义时不猜测历史归属。
- 新增的 `statistics_history` 是过滤视图，不复制数据，只向服务端开放。统计 Worker、公开边界计数和数据库统计函数统一使用它，编辑、导入和撤回继续使用真实明细表。
- 个人分析的汇总及 Dashboard 统计只使用符合规则的明细；账号和记录核对入口仍保留手动内容。补充记录指标不再加入统计概览。
- 排除标记独立于记录和撤回日志，删除手动内容、重新导入、撤回修改或清理过期版本均不会清除。撤回仅还原业务内容，不恢复已经被手动操作过的整池统计资格。账号注销时随用户数据清理。

例如账号 A 的国服限定池有 100 条导入明细，只手动修改其中 1 条，该范围的 100 条全部退出统计；账号 B 的同池、账号 A 的其他区服和未修改卡池继续参与。手动补充一千抽也不会给统计增加一千抽。

统计页和导入／修改页已标注整池排除范围、跨池操作影响及持续排除规则，说明同时适用于桌面、手机及中英文界面。

## 后续正常卡池与历史中断

前池被排除，不会自动排除下一个正常导入的卡池。下一池的抽数、各星级数量、可分类的目标比例以及池内实际获得记录继续参与统计；依赖前池状态的指标单独判断可信度。

- 排除标记新增历史时间起止边界和时间未知标识，只保存账号、卡池及时间，不保存被排除池的抽数、稀有度、获得对象或保底结果。首次标记和后续导入、修改、删除都保留并扩大边界，删除或撤回不能缩短边界。
- 中断范围取已保存的历史边界与目录中卡池开放时间的并集。卡池仍开放或记录跨池交错时，不会因另一池出现六星就提前认为中断已经结束。没有可核实的时间边界时保守维持未知。
- 同一保底范围中，中断后的首个六星间隔不进入平均值和分布。中断结束后的可信常规六星记录将六星状态重置为零，从下一抽开始恢复完整区间。五星由常规五星或六星独立重置；免费十连和直接赠送不重置常规保底，情报书遵循现有常规抽取规则。
- 共享限定池、重构角色同系列及池内独立保底分别隔离。不同登录用户、游戏 UID、区服、其他系列和不共享保底的池不会连带丢失保底资格。
- 重复获取、潜能及溢出配额不能通过一次六星重置补全持有历史。中断后的相关配额不计入，个人账本标记持有历史不完整；资源面板提示只包含可核实贡献。旧 SQL 图鉴和配额计算使用额外过滤视图，保守移除存在角色历史缺口账号的副本推断。
- 系列累计奖励和一次性目标保障也不从零推断；普通保底恢复不会恢复累计历史。后续可信目标获得可证明已经获得该目标，但不推断其是否恰好为累计阈值保障。
- 统计面板显示未知间隔数量及持有历史覆盖情况；保底卡片显示“未知”；时间线保留本池实际抽数，同时将无法核实的出货间隔标为“继承未知”。

复现示例：A 池有 70 抽，B 池正常导入 10 抽并在最后一抽获得六星。A 池被排除后，B 池仍计 **10 抽、1 个六星**，首段间隔为未知。B 池随后又完整抽取 5 抽获得六星时，新增的 **5 抽间隔**进入平均值与分布。

JS 统计和个人快照通过 `prepareStatisticsContinuity` 共享状态判断；旧概览及公开缓存使用 `statistics_pity_intervals` 过滤视图计算可信间隔。中断边界扩大时使相关单池、合池及个人快照重新计算，边界不变的重复编辑不重复扣减贡献。

## 发布与重新计算

上述迁移和前向修复已在现有正式库执行，不得再次套用非幂等创建迁移。每次手动操作与排除标记在同一事务中保存，失败回滚不会留下排除标记。持久标记不加入可撤回的业务增量。

公共统计计算版本升级为 `public-statistics-v6`，个人分析计算版本升级为 `5`。迁移清理旧统计缓存，修正单池和合池计数，并将相关任务标记为待重算。首次排除时只读取该账号、区服和卡池的原有贡献并一次性扣除，按既有依赖规则使相关快照失效；后续被排除范围的操作不会反复扫描并扣减贡献。正常导入继续沿用增量计数。

现有正式库已更新统计计算程序及 schema 5 个人分析 Worker。正式站 API 仍使用 v4 读取合同，生产统计程序暂时以相同版本输出新计算结果，避免只迁移数据库就让现有页面读不到快照。仓库新 API 的 v6 切换需在网站发布时同步；本次没有发布网站。新环境按完整迁移顺序准备结构，预热对应版本快照后再启用读端。

## 验证

`scripts/verify-manual-statistics-exclusion.mjs` 在真实本机 PostgreSQL 使用正式库的生成区服字段执行迁移，验证旧数据回填、全服及个人排名、图鉴、单池和合池计数、整池退出、不同用户／UID／区服隔离、跨池移动、撤回仍排除、删除后重新导入仍排除、补充记录排除，以及表和视图权限。定时任务的触发器和目录计数使用仓库实际迁移；旧统计函数在此测试中使用同名最小函数验证读源替换。

相关单元测试验证 Worker 使用过滤视图及持久标记、删除手动记录后的个人分析仍排除、卡池别名映射、整池对观测和资源结果的隔离、预览数据遵守同样规则，以及原有个人分析和保存合同。原有版本撤回数据库测试继续适用。

`scripts/verify-statistics-continuity-sql.mjs` 在本机 PostgreSQL 加载 baseline 中实际的 `get_global_stats`、`refresh_public_pool_analytics_cache` 和 `get_pool_type_quota_stats`，执行待发布迁移并验证 70+10 场景、可信重置恢复、删除后边界保留、前池继续垫抽后的再次失效及视图权限。新增中断单元测试同时覆盖五星／六星独立恢复、免费与赠送、重叠卡池、系列隔离、持有历史不完整、Dashboard 和时间线空值展示。
