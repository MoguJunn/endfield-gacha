## 定位与验证

首次性能迁移后，正式任务仍返回 SQLSTATE `57014`（60 秒超时）。继续采集受限的真实执行计划，发现两个剩余问题：历史中断检查的反复扫描，以及保障统计的约 1.3 万 × 1 万次匹配；后者单步约 28 秒。补充优化后，正式任务完成并成功发布，未仅靠增加任务超时解决。

- `node scripts/verify-global-summary-pity.mjs`：临时真实 PostgreSQL 中，优化前后逐行间隔及完整概览 JSON 一致。覆盖多账号/区服、继承与重构系列、中断、排序、免费与赠送、无效记录，以及首次 120 抽保障和后续出货。
- 34,404 条隔离样本：完整概览约 354 → 273ms；本机数字不代表生产耗时。
- 小游戏迁移在临时 PostgreSQL 中通过存档乐观锁及权限验证；未使用真实用户进行领取或购买测试。
- 线上再次检查：新增表启用行级访问控制，游客和普通用户不可直接访问；三个函数对游客和普通用户不可执行，仅 service_role 可执行。
- 生产概览接口确认读到新快照；图鉴接口正常读取其独立快照，按原调度继续更新。
