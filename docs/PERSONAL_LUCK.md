# 个人概览的手气评价与高光

桌面入口为 `/dashboard?view=overview`，手机入口为 `/m/overview`。两端使用同一套 `PersonalLuckOverview` / `PersonalLuckPanel`，从已有的、按登录用户隔离的 `personal_statistics` 快照读取结果。

## 数据与评分

- 后台 `buildPersonalStatisticsSnapshot` 读取当前用户的完整历史、目录、补录和 `home_version_timeline`，生成附加字段 `luck`（载荷版本 1，计算版本 `calculationVersion=2`）。不会用浏览器已加载的一页记录代替完整历史。
- 每个游戏账号和区服分别计算，不混合保底或连续不歪记录。限定与复刻参与评分，角色和武器分开；免费抽和赠送排除，情报书的实际抽取保留。
- 概率沿时间线连续还原，之后再按版本汇总；最近三个版本含当前版本与前两个已开始版本，趋势对比此前三个版本。空版本保留，完整武器申领不跨版本拆分。
- 版本通常按抽取时间归属。更新当天（UTC+8）提前开放的新卡池，按 `home_version_timeline.pool_ids` 归入当期版本；武器沿用显式 `character_pool_id` 关联。只修正更新当天早于计划时间的当期卡池，旧卡池和其他日期仍按时间归属，不移动原始时间、不重置保底。
- 版本走势图的主数字为实际非免费抽数 `observed`，评分样本 `sample` 不同时另外标注“参与评分”。无法还原进度的抽取保留在实际抽数中，不伪装成可评分样本。
- 两个分项分别使用 `(实际数量 − 预期数量) / sqrt(预期数量 + 4)`，六星占 40%，UP 占 60%。S ≥ 2，A+ ≥ 1，A ≥ 0.25，C ≤ −0.8，其余为 B。这是试行分档，不是概率、置信区间或玩家排名。
- 有有效样本就评级；角色不足 160 抽、武器不足 80 件或评分依赖推定进度时标记暂定。空记录和不合法数量不输出等级。

## 连续性和高光

奖励事件可能占用序号。明确的非抽取事件不会增加抽数、消耗保底或打断连续性。限定角色池在已确认累计 60 次付费抽、有免费十连、不同批次之间只跳过一个序号时，可按一次情报书奖励节点推定续算；受影响的概率样本单独计数并显示暂定提示。

无法解释的缺口仍使相关进度未知；之后才开放的独立卡池可以从零确认，共享六星保底和复刻系列不会直接重置。补录或无法确认身份的记录不能冒充可评分样本。

多彩只展示同次完整十连中的双彩及以上。最快出金与连续不歪附带实际物品、公开目录头像、卡池和日期；必出 UP 保底不计入连胜。没有相应记录的高光页签隐藏，不用普通一彩填充。

## 本地验证与上线边界

相关测试覆盖计算、版本边界、奖励推定、账号隔离、快照生成、旧快照等待、账号切换、退出登录、高光和折叠说明；浏览器另检查桌面和手机路由及布局。

此字段通过已有后台统计任务生成，不增加数据库表。上线时须同步更新前端和统计 Worker，等待个人快照按正常计划重新计算。旧快照没有 `luck` 时页面显示等待提示，已有统计与图鉴仍可查看，不在访问页面时即时重算全部历史。

2026-10-31 版本归属修正通过 `2026103104_personal_luck_release_boundaries.sql` 升级既有手气补算 RPC，候选只选择尚未达到计算版本 2 的结果；仍按每页最多 20 份快照、修订和租约保护合并 `luck`。正常统计 Worker 和补算程序都需同步更新，再执行既有一次性补算服务。其他指标、原统计时间和用户历史保留，发布时推进快照修订以失效浏览器缓存。

凭据、SSH 配置、测试账号、数据库匿名样本和预览连接脚本均不属于正式实现，不应提交。
