# 武器池三期时间与版本日历同步

本文说明限定武器池的三期截止计算、角色池关联和日历同步要求。

## 后台操作

在卡池管理中编辑限定武器池，设置开始时间后，“同期开启的限定角色池”可自动识别，也可手动选择。自动识别优先采用北京时间同日唯一限定角色池，其次采用当前正在开启的唯一限定角色池；常驻、辉光庆典及重构池不占限定角色期次。不能唯一识别时由管理员选择。

从所选角色池算第一期，预览连续三期，点击“一键填入第三期截止时间”将第三期结束时间填入表单。后续期次未公布时，以最新已知期次结束时间为基础，每缺一期加 21 天，界面明确标注估算。若已登记第三期但缺少截止时间，则从其开始时间估算 21 天。按钮不会自动保存，也不阻止人工修改结束时间。

关联保存在 `pools.character_pool_id`，引用限定角色池的 `pool_id`。未手动选择时，保存使用当时的自动识别结果；保存后关联固定，重新切换“自动识别”可按当前开始时间重新识别。改为常驻武器池或其他类型时清空关联。角色池时间调整后，需再次点击填入并保存，武器池不会被后台悄悄改写。

## 数据库部署与既有日期修正

`supabase/migrations/2026100701_weapon_character_pool_schedule.sql` 新增关联字段、引用与类型校验，并原位扩展现行 `admin_upsert_pool_with_aliases` 的字段保存；认证、别名、阵容及事务边界继续由原 RPC 负责。既有限定武器池应核对并回填可唯一识别的关联，保留原截止日期。部署前备份并核对关联候选，部署后通过后台重新预览需要修正的日期；估算日期在官方公布后应重新填入。

新环境使用已包含迁移的生成 baseline；既有环境执行新增迁移一次，不能重复套用完整 baseline。SQL 验证入口 `supabase/tests/weapon-character-pool-schedule.sql` 使用回滚事务，覆盖重复应用、RPC 保存读取、拒绝非限定角色关联、清空关联及匿名调用拒绝。

## 独立版本日历

主站 `/api/stats?type=version_calendar` 从数据库返回卡池 `startsAt / endsAt`。独立 `endfield-version-calendar` 项目以该数据为卡池时间来源；本地整理内容仅补充活动、样式与无数据库数据时的备份，不能覆盖已经读到的卡池时间，明确的空截止时间也保持为空。跨版本显示仍按各版本边界裁切。

日历卡池同时公开 `poolKind`、`extraSubtype`、`extraSeriesKey`、`extraSeriesPhase`，保留重构分类与后台维护的系列期次。重构角色池显示“重构寻访 · 第N期”，重构武器池显示“重构申领 · 第N期”，期次不按跨版本卡池数量推算。未维护有效正整数期次时仅显示类型；旧第六版离线备份标注第一期。

`history.pool_version` 是官方逐条记录的期次，用于统计分期；`extraSeriesPhase` 是卡池系列配置，用于日历标题。不能用缺失的官方记录期次覆盖后台系列值，也不能用标题的第 N 期回填用户历史。

起止日期均为空的卡池无法定位到时间轴。手动脚本 `supabase/manual/data-backfill/20261007_fill_danqing_reconstruction_weapon_dates.sql` 仅在目标武器日期仍为空、同系列同一期角色池契约符合时补齐同期暂定日期；已有不同人工日期会拒绝覆盖。该脚本针对特定历史数据，执行前须备份并核对候选，不能作为通用日期生成器。日常日期通过卡池管理维护，重构申领不采用限定武器的三期规则。

保存卡池后，主站已有公共缓存失效流程继续生效；独立日历沿用其 API/CDN 缓存时效，已打开的页面需重新载入，不宣称实时推送。主站和独立日历需要分别部署。

维护开始与版本开启是不同时间。“版本更新维护前”应采用已确认的维护开始时间，不能套用新版本开启时间。专项修正脚本 `supabase/manual/data-backfill/20261007_correct_reconstruction_maintenance_end.sql` 针对旧卡池误填截止，执行前须核对脚本目标与备份；其他未公布时间不据此推测。

活动应按官方名称、独立起止时间和海报来源维护。例如 [天地墨显活动说明](https://www.bilibili.com/opus/1256308860049686529) 的签到截止为维护前；其他独立日程不能套用该截止。常驻活动的奖励截止也不表示活动永久关闭。独立日历的官方正文与原图来源约定保存在其 `assets/events/OFFICIAL_SOURCES.md`。

## 不显示或未同步时

1. 先查看后台起止时间、启用／可见性、版本绑定及重构子类／系列期次。数据库 `startsAt: null` 无法定位到时间轴，`endsAt: null` 应保持未知；字段缺失才允许活动备份补充。
2. 检查主站 `version_calendar` 与日历 `/api/v1/events` 的卡池值及 `Age / X-Vercel-Cache` 响应头。主站缓存为 `s-maxage=300, stale-while-revalidate=3600`，日历为 `s-maxage=60, stale-while-revalidate=300`；正文 `source.mode=origin` 仍可能来自 CDN 缓存。
3. 缓存传播后刷新已打开页面，核对卡池真实 `end` 与版本裁切后的 `displayEnd`。跨版本裁切仅控制绘制，不改变后台截止或常驻属性。
4. 若仍异常，分别定位主站 DTO、日历服务端合并、公开序列化和浏览器再次合并；日期与重构期次须完整保留，不通过再填一遍数据库掩盖前端合并问题。

## 统计边界

日期和关联维护不应修改用户历史或统计算法。对象首获与任意六星保底是不同指标，观测结果包括免费十连；不能将所有超过 80 的值截断或删除。跨格式重复导入需按事件身份单独核对，并保留十连内合法的重复结果，具体口径见 [STATS_OBSERVATION_CONTRACT.md](STATS_OBSERVATION_CONTRACT.md)。

实现入口：`shared/weaponPoolSchedule.js`、`src/hooks/admin/usePools.js`、`src/components/admin/pools/PoolEditDialog.jsx`；日历端入口为独立项目的 `lib/calendar-core.js`。
