# 抽卡数据增量版本与撤回

工作台的「修改记录」入口支持撤回最近 180 天内的最近 5 次修改。两个限制取交集；一次数据库事务是一个版本，范围是同一登录用户的全部游戏账号。选择第 N 条记录，会撤回最近 N 次修改，回到该条修改之前。撤回也创建新版本，因此可以撤回刚才的撤回。

版本从迁移启用后开始记录。现有数据作为当前状态保留，不生成虚构的旧版本；迁移之前的修改没有可撤回的增量。

## 存储与资源控制

| 数据 | 存储方式与保留范围 |
| --- | --- |
| 当前抽卡明细和补充记录 | 沿用 `history`、`account_data_workbench_entries`，各保留一份当前状态 |
| `account_data_revisions` | 用户、事务、父版本、时间、变化数量、撤回收据等小体积元数据；最多保留 180 天 |
| `account_data_revision_deltas` | 只保存变化路径、变化前后值、行内部 ID、账号和区服；只保留最近 5 次且不超过 180 天的内容 |
| 临时保存校验凭证 | 15 分钟有效；使用后立即清空请求和可信操作副本，保留摘要和收据以支持精确重试；未使用且过期的凭证由清理任务删除 |

JSON 对象按字段、数组按元素递归比较。修改一项获取记录不复制整个卡池存档；新增或删除时，只记录该行的必要内容，不复制账号全量数据。`pity`、`batch_id`、更新时间和乐观锁版本号等派生字段不进入业务增量。已有审计表仍可读取迁移前的数据，迁移后同一事务不再重复写第二份业务变化副本。

新增版本时，按用户索引立即清理第五次之外的增量和超过 180 天的版本。`prune_account_data_revisions()` 负责清理不再活跃用户的过期版本及未使用的过期校验凭证。迁移检测到 `pg_cron` 时会注册每日任务 `prune-account-data-revisions`（`17 3 * * *`，时区由数据库 cron 配置决定）。未启用 `pg_cron` 的部署，需要让现有服务端定时任务每日调用此 RPC，才能及时释放不再活跃用户的过期内容。

撤回预览只在数据库函数内临时构建被修改行的还原计划；不持久化全量快照，也不把行内容返回浏览器。撤回只重算受影响账号和卡池的保底数据；个人分析失效沿用主站现有触发器和后台快照队列。

## 保存、确认与并发

1. 数据库行触发器把同一用户、同一事务中的新增、修改、删除合并为一个版本。使用内部 `id` 与 `user_id` 定位，避免不同游戏账号的 `record_id` 相同而撤回错行。
2. 预览返回新增记录删除量、删除记录恢复量、修改内容还原量，以及涉及的账号和卡池。跨卡池修改会列出当前卡池和恢复后的卡池。
3. 用户勾选确认后提交目标版本、预览令牌和请求 UUID。数据库重新生成计划并比较令牌；预览后出现新写入时，返回冲突并要求重新预览。
4. 撤回在一个事务内执行。沿用工作台的数据表加锁顺序，并加用户事务锁；中途失败全部回滚。重复请求只返回原收据；同一请求 UUID 用于不同目标或令牌时拒绝执行。
5. 物理删除后的恢复也递增明细或补充记录的版本号，旧页面副本不能再次覆盖恢复后的数据。

浏览器不能直接访问版本表。API 从当前登录会话确定 `user_id`，不接受客户端指定数据所有者；只有服务端 `service_role` 可调用公开的列表、预览、撤回和清理 RPC。内部还原计划 RPC 未开放给客户端。

工作台有未保存草稿或保存结果尚未确认时，「修改记录」按钮禁用。撤回结果尚未确认时保留原请求重试，避免超时后重复执行。

## 迁移与正式发布

新增迁移：`supabase/migrations/2026101401_incremental_account_data_revisions.sql`。依赖以下工作台迁移及主站现有历史明细、保底重算和个人分析队列：

- `2026100911_create_account_data_workbench.sql`
- `2026100912_admin_pool_catalog_roster_and_recalculation.sql`
- `2026100913_atomic_workbench_workspace.sql`
- `2026101400_exclude_manual_statistics.sql`：记录账号、区服和卡池的持久排除标记。被手动添加或修改过的整池不参与统计，撤回不清除排除标记。

迁移在一个事务中执行。如果原子提交函数的请求比较逻辑与预期定义不同，整次迁移会停止并回滚，防止校验副本压缩后破坏幂等判断。

2026-10-14 已在现有生产库执行依赖迁移、本迁移和前向修复 `2026101402_restore_revisions_generated_history.sql`。后者保证恢复删除记录时不显式写入 `server_scope` 等数据库生成列。生产回滚事务验证保存、整池排除、撤回及删除恢复通过，未保留测试记录；每日增量清理任务已注册并启用。执行、备份和 Worker 衔接见 [生产迁移记录](PRODUCTION_WORKBENCH_MIGRATIONS_20261014.md)，统计规则见 [手动数据的统计隔离及迁移状态](MANUAL_DATA_STATISTICS_EXCLUSION.md)。本次没有发布网站；新环境仍须按依赖顺序准备结构并预热对应版本快照。

## 真实账号本机预览与验证

在已经运行的真实账号本机预览上复用只读数据，启动独立数据库预览：

```powershell
$env:WORKBENCH_PG_TEMP = 'D:/Learning/Endfield Gacha/_tmp'
$env:WORKBENCH_INTEGRATION_PORT = '5189'
node scripts/preview-workbench-integration.mjs --real-account --revisions --source-url http://127.0.0.1:5187
```

本次预览加载 4 个真实游戏账号、2108 条历史。桌面为 `http://127.0.0.1:5189/data-workbench`，手机布局为 `http://127.0.0.1:5189/m/data-workbench`。保存与撤回写入本机临时 PostgreSQL；浏览器刷新保留本机修改，停止服务后清理数据库，重新启动时从来源重新载入。浏览器的生产 API 和认证请求在该预览中被阻止。

相关验证命令：

```powershell
node scripts/verify-account-data-revisions.mjs
npx vitest run api/__tests__/accountDataRevisions.test.js
node scripts/verify-workbench-revisions-ui.mjs
```

数据库验证覆盖同事务合并、跨账号相同记录编号、字段和数组增量、派生字段排除、插入和删除的恢复、版本窗口、过期清理、权限、精确重试、预览冲突、跨表事务、统计失效与并发撤回。接口测试覆盖会话绑定、伪造所有者、BIGINT 编号、预览和请求编号必填以及受控冲突。

真实账号浏览器验证覆盖「修改 → 规则验证 → 保存 → 撤回影响预览 → 勾选确认 → 撤回 → 撤回刚才的撤回 → 连续撤回两次 → 刷新核对」，并检查手机布局、最近五次限制及页面渲染错误。
